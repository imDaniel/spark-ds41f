## Isolated dot-layout screen

The archived `evidence/screen-dot-driver.py.txt` varies only the launch layout of the existing compensated dot (4/8/16/32 warps). It checks source hashes for dot, consumer and mHC against the r6x candidate before executing in the retained candidate image where those three files are identical. This is a same-source kernel experiment, not a whole-model r6x result. No prototype is installed into the serving source. The rejected screen driver is retained byte-for-byte as historical execution evidence, not a maintained release module.

The rank-0 screen covers 1/4/5/6/16/96/128/205 rows, H=5120, 16 graph dose cases per layout including zero and near-collinear writers, independent projector plus stock mHC exact output comparison, stable graph addresses and compensated-dot FP64 error checks. Zero rows retain poisoned dot entries. Timing uses 11 interleaved order rounds, 128 dot calls or 16 complete dot-plus-mHC calls per captured graph and 12 replays per sample. Every window and compilation metadata is retained in `evidence/dot-screen-rank0.json`. 205 rows is an ordinary-consumer diagnostic, not the actual SP path. The test-only WORLD=1 declaration does not prove distributed correctness.

All 32 layouts passed those correctness checks, with no spills. At 1–6 rows, the current 8-warps layout takes 2.13–2.18 us for dot and 13.32–13.47 us for dot plus mHC; alternative layouts are slower. Larger shapes show mixed local changes without a consistent total-path gain. **Keep 8 warps; do not append a runtime patch from this screen.** Timing variability and graph-buffer placement prevent interpreting isolated large-shape differences as a model speedup.

Two preparation failures are retained in the private operation receipts: the first screen command inherited the vLLM entrypoint and failed before running a kernel; it was rerun with an explicit Python entrypoint. The first image preparation rejected non-file entries in the archive membership check; the deletion list now comes strictly from the actual Git deletion diff. Both resulting images passed all source/native checks. Neither failure changed an existing configuration or service image.
