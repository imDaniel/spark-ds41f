# Owned sixty-case quality capture

This is source/CPU-tested schema-7 integration, not an execution freeze, model
result, semantic PASS, applied-dose proof, or baseline promotion. Schema 6's P1
warm4K dispatch and limits are unchanged. The new lane is reached only through a
new immutable manifest admitted by the existing held HTTP lifecycle.

## Fixed scope and existing owner

One selected A188 or B197-OFF arm and one of unloaded/loaded0/loaded1/loaded2/
loaded3/loaded4; exactly sixty original reviewed R2 prompts, serial concurrency
1, original PR8 `model --no-score`, natural EOS and default native thinking/high.
The 2,048 generation ceiling counts all generated IDs, including reasoning. No
output repair, semantic retry, hidden queue, segmentation, fixed-length setting,
thinking override, extra tool, candidate-code execution or arbitrary argv exists.
Unloaded omits steering fields; loaded0 retains the loaded profile and scalar 0.

The bridge reuses the existing normal TP4 renderer, exact arm image/native source
and ready observer, original locks/epochs/guards/watchdog, log collection, owned
client subprocess, and exact-ID teardown with positive four-rank drain. It does
not introduce another launcher or change an earlier capsule. Keep-stopped remains
required. Recovery inventories now include both quality modules, so use a new
reviewed controller checkout/capsule; do not replace files under an active freeze.

After any primary attempt is retained, schema 7 cannot retry within that capsule.
A new selection/attempt must be separately reviewed and must retain prior errors.
An HTTP result named `passed` is only the existing lifecycle's capture-completion
gate. The added fields explicitly say `CAPTURE_COMPLETE_AWAITING_TERMINAL_DRAIN`,
`semantic_scoring=NOT_EVALUATED`, and `comparison_eligible=false`. The outer held
terminal still requires positive drain. No complete-capture result claims it.

## Manifest delta and budgets

The selected HTTP job, immutable arm identity, baseline inputs, registered policy,
node inventory, protected roots, source closure and existing entrypoints are the
same as the schema-6 bridge. Change only `http_service.schema_version` to 7 and
replace `legacy_case` with this exact data object:

```json
{"workload":"quality_pilot60_v1",
 "corpus":{"path":"ABSOLUTE_SITE_CORPUS_PATH","sha256":"ACTUAL_CANONICAL_CORPUS_SHA256"},
 "request_seconds":"REVIEWED_POSITIVE_INTEGER",
 "max_response_bytes":"REVIEWED_POSITIVE_INTEGER",
 "max_header_bytes":"REVIEWED_POSITIVE_INTEGER"}
```

The strings above are placeholders, not admissible literal values. All three
bounds must be actual positive integers frozen before execution; there are no
new numeric defaults. Request seconds must fit `client_seconds - 5`. The existing
client range 106–600 seconds, job ceiling 7,200 seconds and outer lease 10,800
seconds are preserved. All sixty `/tokenize` preflights, five finite PR8 metrics
reads and generation share one client deadline, with five seconds reserved for
receipt completion. No lease extension, answer-budget shrink or automatic resume
is performed when they do not fit. Such a pilot is partial/failed evidence, not a
successful subset. A hard process kill may leave only earlier durable artifacts;
absence of the summary is incomplete, not sixty successes.

Per-request monotonic checks and remaining-time socket timeouts bound transport
admission/read progress. Stdlib HTTP body reads use `read1` where provided and
refresh the real socket timeout. These are not a separate per-request OS process
supervisor; the unchanged owned client/job supervisor supplies the hard overall
limit and descendant cleanup. Transport bounds classify overflow as evidence
failure, never as a shortened valid answer. The source tests do not prove that
60 natural-thinking answers fit 600 seconds.

## Immutable corpus and true input binding

The canonical corpus has exactly these fields:

- `schema_version: 1`, `workload: quality_pilot60_v1`, `model: deepseek-v4.1-flash`.
- `material_sha256`: the fixed reviewed R2 checksum-file hash.
- `prompts`: absolute path and SHA-256 of the exact generation-only JSONL.
- `tokenizer_identity` and `artifacts`: the existing full legacy native tokenizer,
  source, asset, weights-manifest and runtime-metadata bindings, without historical
  document construction or input-length padding.
- `default_rendering`: `thinking: true`, `reasoning_effort: high`,
  `add_generation_prompt: true`, `overrides: {}`. This records native defaults;
  the request does not inject those settings.
- `cases`: sixty ordered objects containing only `id`, `category`, `language`,
  `prompt_sha256`, and complete actual `input_ids`.

The non-token case projection is pinned to SHA-256
`4ccde61e2aaa825ce346e5569395054e445b6602d46435395e04e262473c3eac`.
The exact prompt JSONL is pinned to
`8cdcf6143d80d4776c052166a9764d36d8b5020038ad24118e352f3493cf4ca0`.
Gold, reference code and rubric are not model inputs or client source imports.
A portable preparation is not a site corpus. Actual site binding and provenance
must precede admission; synthetic IDs in tests are never admissible field inputs.

The client captures an immutable sixty-slot inventory before preflight. All sixty
live `/tokenize` responses must match every complete frozen vector and count
before opening the first generation request. A mismatch stops preflight immediately
and leaves all sixty response slots NOT_RUN. Every generation response separately
must return the same root prompt IDs, complete output IDs and consistent usage.

## Evidence and failure behavior

The source-only client imports the exact PR8 inventory and exact five-module
quality closure, including capture and the reused legacy asset validator. No
ambient toolbox imports, stale bytecode, model imports or caller-selected module
paths are used. The client module aliases its own existing loader in isolated
`python -I -B` execution, rather than importing a second ambient copy.

`quality-capture/` retains the original capture files, plus raw and recorded live
`tokenize-NNN` receipts, immutable tokenize requests, one complete live-tokenization
index when available, and five bounded raw `metrics-NNN` receipts on a complete
run. Identity and summary both carry identical response/header/request bounds.
All transports use the same owned loopback origin, disable proxies/redirects and
retain bounded raw non-success, malformed or partial bodies. Metrics must contain
actual finite nonnegative running/waiting gauges; initial idle is explicitly zero,
not inferred from a missing endpoint. One infrastructure failure stops subsequent
network admission, including trailing metrics. Wrong/empty/refused or invalid
answer JSON remains model content, never a transport retry.

The controller binds runtime context to its own durable event, exact four-rank
container/config identities and readiness bytes. The receipt validator rehashes
identity/index/prompts, all generation/raw/request/record artifacts, live-token
requests and vectors, metrics bytes/initial idle and Content-Length consistency.
It reconciles all sixty ordinary PR8 rows, rather than trusting PR8's successful-
subset digest. Truncation remains separately visible even if later content scoring
would find a complete answer.

The current native worker observer does not prove per-request applied numeric dose
or the native final-answer reasoning parser/configuration. Therefore the capture
retains `applied_state_evidence.status=UNVERIFIED` and
`context.final_answer_extraction.status=UNBOUND` with its exact native content-field
path. No arbitrary supplied hash upgrades either status. A separate reviewed
parser/runtime binding and offline semantic evaluator must resolve those fields.
Untrusted Python remains unexecuted until its separate isolation gate is met.
